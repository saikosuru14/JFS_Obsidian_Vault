# G1 Garbage Collector

## Overview
G1 (Garbage-First) is the default collector since Java 9. It divides the heap into many equal-sized **regions** (~1-32 MB) that are dynamically tagged Eden, Survivor, or Old. It aims for a **soft pause-time target** rather than pure throughput.

## Why It Matters
G1 is the balanced default for most server workloads: predictable, tunable pauses on multi-GB heaps without the specialized needs of ZGC/Shenandoah.

## How It Works
- Heap = grid of regions; generations are logical, not contiguous.
- **Concurrent marking** identifies live data while the app runs.
- "**Garbage-first**": collects regions with the most garbage first for maximum reclaim per unit of pause.
- **Mixed collections** clean Young + selected Old regions together.
- Evacuation (copying survivors) compacts as it goes, avoiding fragmentation.

## Key Flags
- `-XX:+UseG1GC` (default) ; `-XX:MaxGCPauseMillis=200` (pause goal) ; `-XX:G1HeapRegionSize=n`.

## When to Use / Avoid
- **Use**: general services, heaps ~4-32 GB, wanting predictable pauses with little tuning.
- **Consider ZGC/Shenandoah**: when you need sub-millisecond pauses or very large (100+ GB) heaps.

## Interview Questions
- **Why is it called Garbage-First?** It prioritizes regions with the most reclaimable space to maximize reclaim per pause.
- **G1 vs Parallel GC?** G1 targets predictable pause times; Parallel maximizes throughput but has longer, less predictable pauses.
- **What is a mixed collection?** A GC that collects the whole Young Gen plus a chosen set of Old regions.
